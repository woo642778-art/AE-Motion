# AE Motion v2.3 Stabilization Batch A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce an unsigned Batch A device-candidate IPA that preserves the Beta 20 feature set, repairs source-framework startup timing, restores the Move/Transform `S_` effects with bounded GPU implementations, hardens common 3D shader failure patterns, forwards Google OAuth callbacks reliably, and refreshes legitimate watermark state consistently in preview and export.

**Architecture:** Keep the original app executable byte-for-byte unchanged and ship one source-built `AEMotionExtensionsHost.framework`. Runtime integration is installed after UIKit and host classes are available through an idempotent retry coordinator. Effect repairs are deterministic XML/GLSL overrides applied during IPA packaging; account and watermark code only refreshes or forwards existing legitimate host state and never manufactures entitlement.

**Tech Stack:** Swift 6, UIKit, Objective-C runtime, SwiftPM, Python 3, XML/GLSL effect descriptors, GitHub Actions macOS 15, unsigned IPA ZIP packaging.

## Global Constraints

- Minimum platform is iOS 15.
- Preserve bundle identifier `com.alightcreative.motion`.
- Preserve display name `AE motion`, icon resources, and the main executable byte-for-byte.
- Ship exactly one AE Motion extension framework: `AEMotionExtensionsHost.framework`.
- Do not use a second injected dylib or manually add `LC_LOAD_DYLIB` commands.
- Do not write directly to private project databases.
- Do not bypass subscription, receipt, account, server-side entitlement, or watermark-removal authorization.
- Do not claim physical-device qualification without device evidence.
- The output is an unsigned device candidate, not a final release.
