# AE Motion v2.0 Preset Platform Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace static preset recipes with a versioned XML preset platform, real application adapters, CRUD/import/export UI, macro/dependency validation, a resource hub, and native Add Effects category-key repair.

**Architecture:** Pure preset schema, XML codec, validation, querying, macro evaluation, adapters, and file storage live in `AEMotionExtensionsCore`. UIKit library/editor/detail/resource screens live in `AEMotionExtensionsHost`. Existing Speed Remap, Easing, Camera Shake, and Color Palette tools receive preset documents through explicit initializers. Effect XML packaging preserves the native Alight Motion keys `transform` and `distort`.

**Tech Stack:** Swift 6, Foundation, FoundationXML, UIKit, UniformTypeIdentifiers, PhotosUI, Swift Package Manager, Python 3 metadata packaging tests.

## Global Constraints

- Minimum iOS version remains 15.0.
- Preset XML must round-trip without losing supported fields.
- Invalid presets must be quarantined instead of crashing the host.
- Speed Remap, Easing, Camera Shake, and Color Palette must apply presets through real adapters.
- Do not write directly to Alight Motion's private project database.
- Move/Transform uses native category key `transform`.
- Distortion/Warp uses native category key `distort`.
