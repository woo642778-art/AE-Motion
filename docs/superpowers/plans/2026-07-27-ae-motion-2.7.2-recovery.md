# AE Motion 2.7.2 Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a device-test candidate that preserves the user-supplied AE Motion 2.7 binary exactly while loading the source-controlled 2.7.2 Home Shell as a separately signable iOS framework.

**Architecture:** The existing `AEMotionExtensionsHost.framework` remains byte-identical. A new dynamic framework named `AEMotionUI272.framework` installs only the new Home Shell hooks. The IPA packager appends one `LC_LOAD_DYLIB` command to verified unused header padding in the host executable, adds the new framework bundle, and rejects any unexpected baseline or executable-section change.

**Tech Stack:** Swift 6, Swift Package Manager, UIKit, Core Animation, Objective-C runtime, C constructor bootstrap, Python 3 Mach-O parsing and deterministic ZIP packaging, GitHub Actions macOS Xcode 16.

## Global Constraints

- Immutable baseline SHA-256: `f72053a38a64ea2dac48e18d248d1b279755e24e0318724015b4fd9356090a6d`.
- Product version: `2.7.2`.
- First candidate build: `840`.
- iOS deployment floor: iOS 15.
- Existing `AEMotionExtensionsHost.framework` executable and metadata remain byte-identical.
- No `AEMotionLegacy`, no `dlopen`, and no replacement wrapper at the existing framework path.
- Host executable changes are limited to Mach-O `ncmds`, `sizeofcmds`, and previously zero-filled load-command padding.
- Code bytes at and after the first executable section offset remain byte-identical.
- Existing Telegram, TikTok, Home, Asset Library, 3D Studio and World Studio markers remain present.
- The output is unsigned and must not be called final before physical-device validation.
- The branch must not be merged into `main` without user approval.
