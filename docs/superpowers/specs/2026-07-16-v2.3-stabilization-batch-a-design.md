# AE Motion v2.3 Stabilization — Batch A Design

## Scope

Batch A starts from `feature/v2.2-beta20-full-effect-restoration` and preserves the currently working launch, project-open, render/export, Extensions, Scripts, bundle ID, display name, icon, and host executable behavior.

The active repair scope is:

1. Diagnose and repair common crash/no-op causes across 3D effects.
2. Reimplement Move/Transform `S_` effects using documented public behavior rather than placeholder XML chains.
3. Diagnose unexpected watermark behavior without changing legitimate entitlement semantics.
4. Diagnose Google sign-in infinite loading in re-signed installations and provide explicit failure handling or a supported fallback path when the OAuth callback cannot complete.
5. Keep the previously reported effect-quality backlog for later batches; no reported effect is removed from the backlog.

Render/export failure is not an active Batch A defect because the current stabilized IPA renders correctly in user testing. Regression coverage remains mandatory.

## Non-goals

- No separate injected framework or manual `LC_LOAD_DYLIB` patch.
- No startup constructor in a second dylib.
- No direct writes to private project databases.
- No silent hiding or disabling of reported effects as the final fix.
- No claim of pixel-identical parity with proprietary AE plugins without reference captures.
- No bypass of legitimate account, subscription, receipt, or server-side entitlement checks.

## Architecture

### Stable packaging baseline

Use one source-built `AEMotionExtensionsHost.framework` only. New code is integrated into this framework and loaded through the already proven Beta 20 path. The main app executable remains byte-for-byte unchanged unless a later device log proves that requirement impossible.

### Effect audit and repair pipeline

Introduce an effect manifest generated from all bundled XML definitions. Each entry records:

- effect ID and display name
- category and source file
- referenced helper effects, textures, masks, and buffers
- parameter types and defaults
- dynamic loops, recursive references, and unsupported operations
- 3D or `S_` classification
- device-test status and failure signature

Static validation must not label an effect as working. Working status requires a recorded device render result.

### 3D common layer

Create shared primitives for perspective projection, homogeneous transforms, camera-space clipping, depth ordering, edge sampling, alpha handling, and finite-value clamping. Individual 3D effects consume this layer instead of duplicating unsafe matrix and sampling logic.

All calculations must reject NaN, infinity, zero-divisor, invalid texture coordinate, and unbounded iteration states before passing values to the host renderer.

### Move/Transform `S_` effects

Inventory every `S_` effect in Move/Transform. For each effect:

- document the public reference behavior and exposed controls
- map controls to a clean-room mathematical model
- implement bounded processing with deterministic defaults
- preserve animation and keyframe compatibility
- verify identity behavior at neutral settings
- verify output at minimum, default, midpoint, and maximum settings

An existing placeholder implementation may be retained only when device comparison shows that it already meets the documented behavior and quality target.

### Watermark diagnostics

Treat the watermark report as two possible defects:

1. watermark appears despite a valid state that should suppress it
2. watermark asset/state is inconsistent between preview and export

Instrument the decision path without logging account tokens or personal data. Record entitlement-state category, export path, selected watermark mode, and final compositor decision. The repair must make preview and export follow one deterministic policy. Legitimate server-side entitlement semantics are not overridden.

### Google sign-in diagnostics

The current package contains the production reversed client URL scheme and matching Google service plist, so the investigation must cover the full callback path:

- sign-in request created
- browser or system authentication session opened
- redirect URL received by the application
- redirect forwarded to Google/Firebase handlers
- credential exchange completed or failed
- Firebase session stored in the available keychain group

Add a finite timeout and visible error state. Infinite loading is not permitted. If re-signing prevents the production OAuth client from accepting the app, show a precise unsupported-signature message and expose only sign-in methods that are actually functional in that build. Do not fabricate a successful account session.

## Error handling

- Fail an individual effect application without terminating the editor.
- Roll back partially created effect stacks.
- Show a diagnostic identifier for reproducible failures.
- Bound all retries and asynchronous loading states.
- Preserve the original project when validation or application fails.
- Never convert an authentication failure into an endless spinner.

## Testing

### Automated tests

- parse every bundled effect definition
- detect missing references and dependency cycles
- reject non-finite transform and sampling values
- test neutral and extreme values for 3D primitives
- verify all Move/Transform `S_` controls are represented
- test Google callback state-machine success, cancellation, timeout, and failure
- test watermark decision consistency between preview and export models

### Device matrix

At minimum:

- iOS 15 and a current iOS release
- one lower-memory device and one modern device
- 720p, 1080p, and 4K projects where supported
- 24, 30, and 60 fps
- still image, video, text, shape, grouped, and transparent layers

### Release gates

A Batch A IPA is eligible for user testing only when:

- launch and project-open regression tests pass
- basic render/export still passes
- no second framework is present
- all Move/Transform `S_` effects have recorded application tests
- sampled 3D effects no longer crash the host
- Google sign-in exits every attempt with success, explicit failure, or cancellation
- watermark behavior is deterministic and consistent with the resolved account/entitlement state

## Later batches

The previously reported Glow, Bloom, Halation, Color, Curves, Lens Blur, Motion Blur, Shadow, Stroke, Saber, Distortion, Warp, Refraction, Fluid, Fractal, Particle, Nebula, Aurora, template-import, duplicate, naming, performance, and unreported catalog defects remain mandatory backlog items. Batch A does not close those reports.
