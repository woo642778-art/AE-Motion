# AE Motion 2.7.2 Build 844 Device Recovery

## Device evidence

Build 843 failed on a physical iPhone. The floating navigation was constrained to a partial host view and appeared over the status bar, the original white Alight Motion header and tab bar remained, and the transparent shell intercepted touches. The legacy promotion also remained because it is generated by `AlightMotion.dylib`, not by the compatibility dylib removed in Build 843.

## Structural corrections

- Wrap the actual full-screen main `UIWindow.rootViewController` in `AEMotionRootContainerViewController`.
- Embed the original host controller below a single full-window `AEMotionShellViewController`.
- Give Home and Tutorials to persistent source-controlled controllers.
- Pass center-content touches through to the host Projects and Templates controllers.
- Keep only the AE Motion header, bottom chrome, navigation, create tray, and source-controlled root content interactive.
- Retire partial controller lifecycle swizzling.
- Load `AEMotionUI272.framework` before `AlightMotion.dylib` so promotion suppression is installed before legacy initialization.
- Replace the exact legacy promotion selector implementation from `AlightMotion.dylib` with a no-op and remove already-visible promotion views.
- Replace the two UTF-16 `Cracked By Blatant` strings without changing the dylib byte length.
- Preserve the existing AE Motion extension and the unrelated compatibility dylib.
