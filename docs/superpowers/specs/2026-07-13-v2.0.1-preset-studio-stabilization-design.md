# v2.0.1 Preset Studio Stabilization Design

## Scope

Only two device-confirmed v2.0 issues are changed:

1. Preset Studio did not expose a usable back path because the favorites filter occupied the left navigation item.
2. Apply Preset opened or selected tools inconsistently instead of applying back to the tool that launched Preset Studio.

All other v2.0 behavior remains unchanged and receives regression checks only.

## Navigation design

The favorites filter moves to the right navigation items. A pushed Preset Studio uses the native navigation back button. If Preset Studio is the root of a presented navigation controller, it shows a close button.

## Application design

A tool opening Preset Studio supplies a `PresetApplicationContext` containing:

- the exact supported target;
- a weak source-controller reference;
- a throwing application handler.

The library filters to compatible presets. Applying a preset validates the target with the core `PresetApplicationResolver`, applies through the source tool's existing adapter, refreshes that tool, and pops back to the source controller.

A standalone Preset Studio resolves every supported declared target rather than blindly using the first target. Multiple supported targets are presented for explicit selection.

## Safety

- Duplicate Apply taps are ignored.
- Adapter output is computed before tool state is mutated.
- A failed color-preset application no longer replaces the current palette with a generated fallback.
- Unsupported and undeclared targets show an error without changing the tool.
