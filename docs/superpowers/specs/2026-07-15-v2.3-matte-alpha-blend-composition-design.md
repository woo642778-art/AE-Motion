# AE Motion v2.3 Matte·Alpha·Blend·Composition Design

## Goal

Deliver one public v2.3 release that adds AE-like editable pre-compositions, full blend-mode groups, modern track mattes, parenting and null layers, channel/alpha tools, and real-time preview without modifying the host main executable or writing directly to private host timeline databases.

## Approved UX

- Long-press a timeline layer to enter multi-select mode.
- Show check controls on layers and a bottom action bar with Pre-compose, Parent, Matte, and Group actions.
- Pre-compose requires at least two selected layers.
- New pre-compositions are editable and openable, not rendered/flattened media.
- The pre-composition duration is automatically trimmed from the earliest selected in-point to the latest selected out-point.
- Move selected layers, transforms, effects, blend modes, mattes, parenting, keyframes, and relative ordering into the child composition.
- Preserve the visible frame before and after creation through coordinate and timing compensation.
- Treat creation as one undoable atomic command.
- Reflect child-composition edits immediately in the parent preview.

## Functional scope

### Blend modes

Support AE-style grouped blend modes: Normal, Darken, Lighten, Contrast, Difference, HSL, and utility modes. The model must include stable identifiers, localized display names, grouping, capability checks, and deterministic reference math.

### Track matte

Use the modern AE model. A target may reference any layer by stable ID regardless of stacking adjacency. Support Alpha, Alpha Inverted, Luma, and Luma Inverted. One matte source may be shared by multiple targets. Reordering must not break links.

### Parenting and nulls

Support pick-whip and dropdown assignment, arbitrary layer or null parents, multiple children, nested chains, disconnect, cycle prevention, and preservation of world-space appearance when assigning or removing a parent.

### Channel and alpha

Support RGBA viewing, channel enable/disable, alpha inversion, premultiply/unpremultiply, RGB preservation, luminance-to-alpha, per-output-channel mapping, and Set Channels/Shift Channels-style operations.

### Real-time preview

All property and structural edits use transactions. Blend, matte, parent, alpha, and channel changes update during interaction. Pre-compose uses a shadow graph for provisional structure, then commits through a verified host command path. Cancel restores selection, ordering, timing, parent/matte links, and visual state.

## Architecture

### Composition core

Create a source-built clean-room graph in `AEMotionExtensionsCore` with immutable composition and layer IDs, dependency validation, cycle detection, timing ranges, transform inheritance, matte references, blend descriptors, channel operations, and pre-composition nodes.

### Shadow transaction layer

A `CompositionTransaction` owns an original graph, provisional graph, current selection, and commit/cancel state. Preview updates are coalesced at display cadence. Structural mutations are isolated until commit.

### Host integration

The host framework may read visible contextual state and invoke only verified host controls or command paths. It must not write private timeline databases, patch the main executable, decrypt proprietary assets, or copy code/assets from uploaded APK/IPA references. Unsupported host contracts fail closed and leave the project unchanged.

### Rendering

Use deterministic clean-room reference compositing for preview verification and tests. Rendering must correctly handle straight and premultiplied alpha, transparent edges, matte inversion, blend reference vectors, and parent transform matrices.

## Safety and compatibility constraints

- Preserve app display name, icon, and bundle identifier `com.alightcreative.motion`.
- Preserve the host main executable byte-for-byte.
- Produce one source-built `AEMotionExtensionsHost.framework` only.
- Produce unsigned IPA artifacts only.
- Do not copy APK/IPA proprietary implementation or assets.
- Do not decrypt `.ta` or other encrypted resources.
- Do not mutate private host timeline/project databases directly.
- Do not use render-and-reimport as the implementation of pre-compose.
- Fail closed when a host command contract cannot be verified.

## Verification gates

1. Swift unit tests for graph identity, timing, cycles, parenting matrices, mattes, blend math, channel mapping, premultiplication, and transaction rollback.
2. `make doctor`, `make test-ios`, and `make build-ios` must pass locally.
3. XcodeGen TestHost must build and run on an iOS Simulator.
4. UI tests must cover long-press multi-select, two-layer pre-compose, cancel rollback, parent pick-whip, matte selection, and live-preview updates.
5. Physical-device qualification is separate evidence and must not be inferred from simulator or static checks.
6. No final IPA is named or presented as release-ready until exact-branch framework build, simulator tests, and device gates pass.
