# AE motion v2.3 Matte, Alpha, Blend and Composition Design

## Status

Approved for implementation as one public v2.3 release. Internal delivery is divided into independently testable composition-core, host-bridge, live-preview and UI slices, but no partial public IPA is released as v2.3.

## Product Goal

Add an After Effects-like compositing workflow to the existing AE motion editor:

- full standard blend-mode groups
- modern source-selectable track mattes
- alpha and channel operations
- Null layers and AE-style parenting
- editable pre-compositions from multiple selected timeline layers
- immediate preview feedback for every supported edit

The feature must remain non-destructive, reversible and safe when the host build does not expose a verified editing contract.

## Approved Interaction Decisions

### Timeline multi-selection

- Long-press a timeline layer to enter multi-select mode.
- Selected layers show a check indicator.
- A bottom action bar exposes `Pre-compose`, `Parent`, `Matte` and grouping-related actions.
- The UI displays selected-layer count and resulting selected time span.
- Leaving multi-select mode restores the normal timeline controls without changing the project.

### Editable Pre-compose

- Pre-compose requires at least two selected layers.
- Selected layers move into a new editable child composition.
- The original timeline receives one precomp layer.
- Double-tapping the precomp layer opens its child composition.
- Child edits update the parent preview immediately.
- The child duration is automatically trimmed from the earliest selected-layer start to the latest selected-layer end.
- Internal layer order and relative time offsets are preserved.
- Transform, effects, blend mode, matte, parenting, masks and keyframes remain on the moved internal layers.
- The generated parent precomp layer begins with a neutral transform.
- Coordinate and timing compensation preserve the rendered result before and after pre-compose.
- The whole operation is one undoable command.

### Blend Modes

Expose the full standard After Effects-style grouped list rather than a short favourites-only set:

- Normal: Normal, Dissolve, Dancing Dissolve
- Darken: Darken, Multiply, Color Burn, Classic Color Burn, Linear Burn, Darker Color
- Lighten: Add, Lighten, Screen, Color Dodge, Classic Color Dodge, Linear Dodge, Lighter Color
- Contrast: Overlay, Soft Light, Hard Light, Linear Light, Vivid Light, Pin Light, Hard Mix
- Inversion: Difference, Classic Difference, Exclusion, Subtract, Divide
- Component: Hue, Saturation, Color, Luminosity
- Matte and utility modes supported by the host contract, including Stencil and Silhouette variants, are exposed only when their semantics are verified.

Mode metadata is stable and Codable. Rendering tests use explicit reference vectors and do not rely on host screenshots alone.

### Modern Track Matte

- A target layer may select any compatible layer in the current composition as its matte source.
- Supported modes are Alpha, Alpha Inverted, Luma and Luma Inverted.
- The matte source does not need to be directly above the target.
- One matte source may feed multiple target layers.
- Connections are stored by stable layer ID and survive timeline reordering.
- Self-reference, missing sources and dependency cycles fail closed.
- Matte source and inversion changes update the preview immediately.

### Null and Parenting

- Null layers are first-class composition layers with no rendered pixels.
- Parent assignment is available through both pick-whip and dropdown UI.
- Any compatible layer or Null may be a parent.
- Multiple children and nested parent chains are supported.
- Reparenting and unparenting preserve the child's current world-space position, rotation, scale, anchor and opacity where applicable.
- Self-parenting and cycles are rejected before mutation.
- Parent changes update the preview immediately.

### Channel and Alpha

Provide an AE-style channel toolset:

- RGBA composite and single-channel preview
- channel enable and disable
- alpha inversion
- premultiply and unpremultiply
- preserve or replace RGB while changing alpha
- create alpha from luminance
- map source R, G, B, A, luminance, full-on or full-off into each output channel
- Set Channels and Shift Channels-style operations

Alpha interpretation is explicit: straight or premultiplied. Transparent-edge tests prevent halo regressions.

### Live Preview

All supported operations use preview transactions:

- sliders, pickers and toggles update while the gesture is active
- duplicate updates are coalesced to display-refresh cadence
- the final pending value is always flushed before commit
- Pre-compose confirmation shows a temporary structural result in the current preview
- `Done` commits one atomic command
- `Cancel` restores layer order, selection, time range, transforms, parent links and matte links
- selection change, host contract invalidation, backgrounding or controller dismissal cancels and restores the original state

## Architecture

### 1. Composition Domain Model

The source-built framework owns a clean-room, Codable composition graph used for validation, preview state and command generation.

Core entities:

- `CompositionDocument`
- `Composition`
- `CompositionLayer`
- `CompositionLayerKind`
- `CompositionTransform`
- `CompositionTimeRange`
- `BlendModeDescriptor`
- `MatteBinding`
- `ParentBinding`
- `ChannelMapping`
- `AlphaInterpretation`
- `PrecomposeDefinition`

Every composition and layer uses a stable UUID. Relationships are ID-based. The graph validates missing references, duplicate IDs, invalid time ranges and dependency cycles.

The v2.1 `ProjectDocument` model remains compatible. v2.3 composition data is translated through explicit adapters rather than silently changing private host records.

### 2. Immutable Commands and Atomic Transactions

Composition edits are represented as reversible commands. Structural commands capture complete before and after graph snapshots for the affected composition boundary.

Required commands:

- set blend mode
- set matte binding
- set parent binding
- add Null
- set channel mapping
- set alpha interpretation
- pre-compose selected layers

`CompositionTransaction` has idle, active, committed and cancelled states. A transaction owns:

- immutable initial graph
- current shadow graph
- selection identity
- affected composition ID
- generated host command intent
- rollback reason when cancelled

Commit and cancel are idempotence-safe. An invalid graph never reaches the host bridge.

### 3. Hybrid Host Integration

The integration is deliberately hybrid:

1. Read a verified editing context and selected timeline-layer handles from an allowlisted host surface.
2. Build or update a shadow composition graph inside `AEMotionExtensionsHost.framework`.
3. Render or request a temporary preview update without modifying private persistence.
4. On confirmation, execute only verified host UI actions or supported mutation callbacks.
5. Re-read the host state and compare it with the intended result.
6. Roll back or fail closed when the postcondition does not match.

The bridge never directly writes the host application's private timeline database, SQLite files or serialized project records. It never patches the main executable. It does not use render-export-reimport as an editing substitute.

Host capabilities are explicit:

- read timeline selection
- identify stable layer handles
- invoke supported multi-select actions
- set exposed property controls
- request preview invalidation
- perform structural actions when a verified action contract exists
- verify the resulting visible host state

Unsupported capabilities are omitted from the UI rather than simulated as successful.

### 4. Preview Rendering Boundary

Two preview paths are allowed:

- Host-native preview invalidation after supported host control mutation.
- Framework-owned clean-room compositing preview for a temporary shadow graph when the host exposes a safe preview overlay surface.

A framework overlay must be clearly temporary, attached only to the current viewer and removed on commit, cancel or bridge invalidation. It must not conceal a failed host commit. After commit, the native host preview is the source of truth.

Blend, alpha and matte reference math uses normalized linear components internally for deterministic tests. Color-management expansion beyond the existing project working-space descriptor remains scheduled for v2.6; v2.3 does not claim a complete HDR color-management pipeline.

### 5. UI Structure

Contextual controls are integrated into the existing editor rather than added as a large independent Extensions hub.

Timeline:

- long-press multi-select mode
- bottom action bar
- compact selection count and span
- disabled-state explanations for locked, incompatible or insufficient selections

Layer compositing inspector:

- Blend
- Track Matte
- Parent
- Alpha and Channels

Pre-compose sheet:

- editable name
- selected layer count
- automatic result range
- temporary live-preview state
- `Cancel` and `Done`

Pickers use searchable grouped lists and show current relationships. Pick-whip interactions include a visible source and target state and cancel cleanly when the gesture leaves a compatible target.

### 6. Performance

- Live value changes are coalesced at display-refresh cadence.
- Structural previews rebuild only affected dependency subgraphs.
- Parent transforms are resolved in topological order and cached per graph revision.
- Matte and precomp dependency caches use stable IDs and revision tokens.
- Preview work is cancelled when superseded.
- UI and host mutation stay on `MainActor`; pure graph, blend and channel math remains Sendable and testable off the main thread.

## Error Handling

- Unsupported host build: do not inject the corresponding control; record a compatibility diagnostic.
- Fewer than two selected layers: disable Pre-compose and explain the requirement.
- Locked or incompatible layer: exclude it or fail the operation before preview, with no partial mutation.
- Missing matte or parent source: reject the binding and preserve the previous state.
- Parent or composition dependency cycle: reject before mutation.
- Preview-render failure: cancel the transaction and restore the original native preview.
- Host commit postcondition mismatch: report failure, remove the temporary overlay and request restoration through the verified host undo path.
- App backgrounding or selection change: cancel and restore.
- Memory pressure: drop preview caches; never discard the transaction's initial graph.

## Security and Compatibility Constraints

- Preserve the host main executable byte-for-byte.
- Preserve display name `AE motion`, existing icon and bundle ID `com.alightcreative.motion`.
- Ship one source-built `AEMotionExtensionsHost.framework` only.
- Produce an unsigned IPA with no provisioning profile, signing certificate or embedded signing material.
- Do not copy proprietary APK or IPA code or assets.
- Do not decrypt encrypted `.ta` or other protected assets.
- Do not write private host timeline or project databases directly.
- Do not use binary patching or a secondary loader framework.
- Fail closed when a host contract is unavailable or ambiguous.

## Testing Strategy

### Core unit tests

- composition Codable round-trip and stable IDs
- graph validation for missing references, duplicate IDs and cycles
- full blend-mode catalogue ordering and grouping
- blend reference vectors, clamping and alpha behavior
- premultiply and unpremultiply round-trip
- channel mapping and luminance-derived alpha
- matte normal and inverted modes
- world-transform preservation while parenting and unparenting
- parent cycle rejection
- Pre-compose auto-trim, layer ordering and relative timing
- Pre-compose transform compensation and exact rollback
- transaction commit, cancel, selection change and background cancellation

### Host contract tests

- controls appear only on allowlisted compatible editing surfaces
- long-press enters multi-selection without triggering an unintended layer edit
- Pre-compose stays disabled for fewer than two compatible layers
- every live interaction requests immediate preview invalidation
- structural preview is removed on cancel and controller dismissal
- a failed or ambiguous host postcondition is reported as failure
- Extensions and Scripts does not gain duplicate composition-editing entries

### Simulator tests

Run through the XcodeGen TestHost once the local setup is pushed and available to the implementation branch:

- iPhone and iPad layouts
- portrait and landscape rotation
- long-press multi-select and bottom action bar
- blend, matte, parent and channel picker interaction
- Pre-compose preview, cancel, commit and reopen
- background and foreground restoration
- memory-warning cache release
- screenshot baselines for key UI states

Simulator evidence is separate from physical-device evidence.

### Physical-device release qualification

- one supported physical iPhone
- one supported physical iPad
- add, save, close, reopen and render a project containing each v2.3 feature family
- verify live preview and cancellation
- verify nested precomps, shared track mattes and parenting chains
- verify the exact IPA framework hash under test

No final v2.3 release claim is made from static or Simulator evidence alone.
