# AE motion v2.2 Beta 19 Contextual Live Preview Design

## Status

Approved design direction: contextual integration into the existing editing UI, with immediate preview updates and a reduced Extensions & Scripts surface.

## Goals

1. Make newly added editing features available beside the host app controls they extend.
2. Update the current preview immediately while the user drags a slider, edits a graph, records a gesture, or changes velocity.
3. Remove editing-only tools from Extensions & Scripts.
4. Fix BCC Edge Glow thumbnail metadata.
5. Detect and quarantine effects that produce black bars, invalid alpha, blank output, or unsafe texture-coordinate behavior.
6. Stop restoring effects to Other merely to meet a numeric target.

## Non-goals

- No direct writes to the host app's private timeline or project database.
- No separate render-export-reimport workflow for live editing features.
- No promise that an unsupported host build will expose contextual controls.
- No reintroduction of quarantined effects without visual and runtime evidence.

## Architecture

### 1. Host Editing Context Bridge

`HostEditingContextBridge` discovers only allowlisted host controllers and controls at runtime. It exposes a narrow interface:

- current editor controller
- selected layer or clip handle when available
- current preview surface
- current playhead time
- safe property mutation callbacks
- preview invalidation callback

Discovery is fail-closed. A control is injected only after the bridge confirms the expected controller role, selector contract, and compatible object shape. Unsupported builds receive no contextual button rather than a nonfunctional demo fallback.

The bridge does not persist or inspect private project records. It sends temporary, user-initiated changes through already exposed host control paths or public UI actions.

### 2. Contextual Tool Placement

Editing tools move from Extensions & Scripts to the related host surfaces:

- Transform panel: Gesture Record and Motion Cleanup
- Keyframe or graph panel: Value Graph, Speed Graph, Easing
- Speed panel: Velocity Ramp, Freeze, Reverse
- Effect controls: effect safety status and live effect parameter updates
- Viewer: temporary live-preview overlay and reset action

Only independent utilities remain in Extensions & Scripts:

- Effect Integrity
- Project Reliability and Project Doctor
- Host Diagnostics
- Preset and resource utilities that do not require the current preview

`Animation Core` is removed as a top-level Extensions & Scripts item. Its components remain reusable but are launched contextually.

### 3. Live Preview Transaction

Every contextual edit follows one transaction model:

1. Read the currently selected object and playhead time through the bridge.
2. Begin a temporary preview transaction.
3. Apply parameter changes at display-refresh cadence, coalescing duplicate updates.
4. Ask the host preview surface to redraw immediately.
5. Commit when the gesture ends or the user confirms.
6. Roll back when cancelled, the selection changes, or the bridge becomes invalid.

Updates are throttled to the screen refresh rate and never require export or file replacement. The preview transaction stores the original values needed for cancellation.

### 4. Effect Thumbnail Contract

BCC Edge Glow keeps the effect ID `com.alightcreative.effects.bccedgeglow` and receives an explicit descriptor thumbnail attribute:

`thumb="thumb/bccedgeglow.png"`

Packaging verifies that the referenced file exists, is a decodable PNG, has nonzero dimensions, and is included at the exact case-sensitive path. The same validation applies to every effect declaring a thumbnail.

### 5. Visual Effect Qualification

Static XML and shader checks remain necessary but are no longer sufficient. Qualification has two explicit stages.

#### Stage A: CI qualification

A clean-room offscreen renderer evaluates supported single-pass descriptors against standard fixtures:

- transparent checkerboard
- full-frame color bars
- portrait frame
- landscape frame
- alpha-edge subject

The CI stage checks for:

- unexpected black bands at frame boundaries
- all-black or all-transparent output
- non-finite pixel values
- alpha loss when the source contains alpha
- aspect-ratio-dependent cropping beyond declared behavior
- output that is byte-identical to the input when the effect declares a visible default
- texture sampling outside normalized bounds when not explicitly clamped or wrapped

Descriptors the clean-room renderer cannot faithfully execute are marked `deviceQualificationRequired`; they are not treated as visually verified.

#### Stage B: on-device host qualification

A diagnostic runner applies each candidate effect in the actual host renderer to the same fixtures and records:

- effect ID and descriptor hash
- host app version and device class
- output metrics
- pass, fail, timeout, or crash result
- optional reference screenshot hash

A crash, timeout, black-bar result, blank output, or invalid alpha result fails the effect. The diagnostic runner restores the previous project state after every candidate and never writes directly to the private project database.

Effects failing either applicable stage are quarantined with the fixture, metric, and reason recorded. Effects requiring Stage B cannot enter Other until a passing device result exists for the current descriptor hash.

### 6. Other Category Policy

Other contains only effects that pass:

- descriptor and dependency audit
- runtime-risk audit
- thumbnail contract when a thumbnail is declared
- CI visual qualification when supported
- on-device host qualification for the exact descriptor hash

The previous `target-count` selection mechanism is removed. The Other count becomes an observed result, not a release requirement. Effects without current visual evidence return to their original category or remain quarantined; they are not used to inflate Other.

## Error Handling

- Missing or changed host selectors: skip injection and record a compatibility diagnostic.
- Selection changes during editing: cancel the preview transaction and restore original values.
- Preview update failure: stop live updates, restore the original state, and show a concise error.
- CI renderer cannot execute a descriptor: mark it as requiring device qualification, not as passed.
- Device qualification timeout, crash, or renderer failure: quarantine the effect.
- Missing thumbnail asset: fail packaging for the repaired effect.
- Unsupported host build: retain diagnostics and utilities, but do not expose nonfunctional contextual editing controls.

## Testing

### Unit tests

- preview transactions commit, cancel, and restore correctly
- update coalescing does not lose the final value
- contextual placement excludes editing tools from Extensions & Scripts
- thumbnail path validation is case-sensitive
- black-bar detection distinguishes declared letterboxing from unexpected bars
- alpha preservation and blank-output metrics
- unsupported descriptors require device qualification
- Other selection has no numeric target dependency

### Integration tests

- inject each button only into its matching host context
- changing a contextual control invalidates the current preview without export
- selection changes roll back an active edit
- BCC Edge Glow thumbnail resolves in the packaged app
- known broken fixture effects are quarantined
- known valid portrait and landscape effects pass qualification
- device results are accepted only when the effect ID and descriptor hash match

### Release gates

- all Swift and Python tests pass
- generic arm64 iOS Release framework build passes
- BCC Edge Glow thumbnail is present and referenced
- no effect enters Other without matching visual-qualification evidence
- Extensions & Scripts contains no top-level Animation Core editing entry
- main executable remains byte-identical
- IPA contains no signing material
- physical iPhone and iPad tests confirm contextual controls, live preview, cancellation, and representative effects
