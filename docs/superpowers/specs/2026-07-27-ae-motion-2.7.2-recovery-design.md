# AE Motion 2.7.2 Recovery and Integration Design

## Status

Approved for implementation on `fix/2.7.2-recovery`.

## Immutable baseline

The only accepted binary baseline is the user-supplied `AE Motion 2.7(2).ipa` with SHA-256:

`f72053a38a64ea2dac48e18d248d1b279755e24e0318724015b4fd9356090a6d`

The baseline `AEMotionExtensionsHost.framework/AEMotionExtensionsHost` executable must remain byte-identical in every 2.7.2 candidate. The baseline app executable may change only in its Mach-O header and unused load-command padding to add one explicit framework dependency. Its executable sections must remain byte-identical.

## Root cause being corrected

The rejected 2.7.1 package replaced the existing `AEMotionExtensionsHost` executable with a wrapper and moved the actual 2.7 implementation to an unbundled sibling executable named `AEMotionLegacy`. That additional Mach-O was not represented as its own framework bundle and could be omitted by recursive signing tools. When iOS rejected or failed to load it, both the existing AE Motion extensions and the new UI hooks disappeared.

2.7.2 prohibits this architecture. There is no `AEMotionLegacy`, no runtime `dlopen`, and no replacement of the existing extension framework.

## Integration architecture

### Preserved 2.7 framework

`Payload/AlightMotion.app/Frameworks/AEMotionExtensionsHost.framework` remains unchanged, including:

- executable bytes,
- Info.plist,
- resources,
- public and private symbols,
- existing Home, extension, tracking, matte, depth, 3D, World Studio, settings and release behavior.

### New 2.7.2 UI framework

The source-controlled Home Shell is built as a separate framework:

`Payload/AlightMotion.app/Frameworks/AEMotionUI272.framework/AEMotionUI272`

The framework has its own Info.plist, executable, bundle identifier, minimum iOS version and version metadata. It installs UI hooks directly from its constructor after the existing 2.7 framework has loaded.

### Explicit Mach-O loading

The app executable receives exactly one appended `LC_LOAD_DYLIB` command:

`@rpath/AEMotionUI272.framework/AEMotionUI272`

The command is written only into verified unused load-command padding before the first `__TEXT,__text` section. Existing commands are not moved or replaced. The original `AEMotionExtensionsHost` load command remains earlier in command order, so existing 2.7 initialization occurs before 2.7.2 UI installation.

The patcher must fail closed if:

- the baseline SHA does not match,
- the app is not a thin arm64 Mach-O,
- the framework command already exists more than once,
- there is insufficient zero-filled header padding,
- the first executable section offset differs from the verified baseline,
- or any executable byte at or after the first section offset changes.

## Release identity

- Marketing version: `2.7.2`
- First candidate build: `840`
- Subsequent build attempts increase only the build number.
- A build is not called final until signed physical-device verification succeeds.

## Home Shell behavior

The 2.7.1 UIKit source is retained and corrected rather than discarded. It provides:

- one Home Shell owner,
- Home, Tutorials, Create, Projects and Templates root navigation,
- adaptive Workspace Home layout,
- native ambient field,
- touch-position spotlight cards,
- interruptible spring motion,
- Reduce Motion and Reduce Transparency behavior,
- and legacy action forwarding through existing accessibility identifiers.

The framework no longer depends on or loads a renamed copy of the 2.7 binary.

## Launch behavior

The final launch path must contain one visual stage. The stock static launch storyboard may remain, but the existing runtime `AEMotionLaunchOverlay` must not produce a second blocking loading stage. The first recovery candidate will disable only the explicitly owned AE Motion runtime overlay and must not remove unrelated host loading or authentication UI.

## Preservation contract

Packaging fails unless all of these match the immutable baseline:

- `AEMotionExtensionsHost.framework/AEMotionExtensionsHost` SHA-256,
- `AlightMotion.dylib` SHA-256,
- every existing file except the allowlisted changed and added paths,
- the original AE Motion framework load command,
- known Telegram and TikTok release strings,
- and required 2.7 feature markers for Home, Asset Library, 3D Studio and World Studio.

Allowlisted changes for the first recovery candidate are:

- app executable Mach-O header and load-command padding only,
- app Info.plist release metadata,
- removal of signing material,
- addition of `AEMotionUI272.framework`,
- addition of a 2.7.2 build manifest.

## Asset Library, 3D and performance phases

The following are subsequent 2.7.2 phases and cannot bypass the recovery gate:

1. Launch overlay cleanup and device validation.
2. Remote asset catalog, previews, background cache and timeline insertion.
3. 3D workspace to actual editable scene, render and timeline handoff.
4. Home/editor performance profiling and animation tuning.

Each phase increments the build number and produces a device candidate. No later phase may modify the immutable 2.7 framework unless its full source lineage is restored and rebuilt as one verified product.

## Verification levels

### Automated

- Swift tests.
- Source-contract tests.
- Xcode generic arm64 framework build.
- Framework install-name and architecture inspection.
- Exact baseline-preservation comparison.
- Mach-O command and executable-section comparison.
- ZIP CRC and signing-material checks.

### Physical device

Required before final release:

- app launch,
- existing AE Motion extension presence,
- Home Shell appearance,
- all root-tab routing,
- existing 3D and World Studio entry,
- existing Cutout, Depth, Tracking and Matte entry,
- background and foreground recovery,
- memory, CPU, GPU and thermal observation,
- and recursive signing of both framework bundles.

Automated verification must never be reported as physical-device qualification.
